# Feature Specification: 歌曲詳細頁與歌詞高亮顯示

**Feature Branch**: `005-song-detail-highlight`  
**Created**: 2025年12月25日  
**Status**: Draft  
**Input**: User description: "從查詢結果跳轉到歌曲詳細頁，並在詳細頁中高亮顯示匹配的歌詞片段"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 從搜尋結果進入歌曲詳細頁 (Priority: P1)

使用者在搜尋結果頁面看到符合條件的歌曲列表，點擊任一歌曲後能夠進入該歌曲的詳細頁面，查看完整的歌曲資訊和完整歌詞內容。

**Why this priority**: 這是最核心的功能，提供使用者從列表到詳細內容的基本導航能力，是後續所有功能的基礎。

**Independent Test**: 使用者可以完全獨立地測試此功能 - 從搜尋任何關鍵字開始，點擊任一結果，確認能看到完整的歌曲詳細頁面，包含歌名、歌手和完整歌詞。這本身就能提供價值（查看完整歌詞）。

**Acceptance Scenarios**:

1. **Given** 使用者在搜尋結果頁面看到多筆歌曲結果, **When** 使用者點擊任一歌曲項目, **Then** 系統應該導航到該歌曲的詳細頁面
2. **Given** 使用者進入歌曲詳細頁面, **When** 頁面載入完成, **Then** 應該顯示完整的歌曲資訊（歌名、歌手、完整歌詞）
3. **Given** 使用者在歌曲詳細頁面, **When** 使用者想要返回搜尋結果, **Then** 應該提供返回按鈕或瀏覽器返回功能
4. **Given** 使用者點擊返回, **When** 返回到搜尋結果頁面, **Then** 搜尋結果和狀態應該保持原樣（包含搜尋關鍵字、捲動位置等）

---

### User Story 2 - 歌詞匹配片段高亮顯示 (Priority: P2)

當使用者是透過歌詞關鍵字搜尋並進入歌曲詳細頁時，系統應該在完整歌詞中高亮顯示所有匹配搜尋關鍵字的片段，讓使用者能夠快速定位相關內容。

**Why this priority**: 這個功能大幅提升使用者體驗，讓使用者不需要在完整歌詞中手動尋找匹配的部分。特別是對於長歌詞，這能節省大量時間。

**Independent Test**: 此功能可獨立測試 - 搜尋特定歌詞關鍵字（如「愛」），點擊任一結果進入詳細頁，確認該關鍵字在歌詞中被視覺化標記（如黃色背景）。即使沒有其他功能，這個視覺提示本身就提供了價值。

**Acceptance Scenarios**:

1. **Given** 使用者搜尋歌詞關鍵字「愛」並獲得結果, **When** 使用者點擊某個搜尋結果進入詳細頁, **Then** 完整歌詞中所有「愛」字應該被高亮顯示
2. **Given** 歌詞中有多處匹配關鍵字, **When** 詳細頁面載入, **Then** 所有匹配處都應該被高亮顯示
3. **Given** 使用者透過歌名或歌手搜尋進入詳細頁（非歌詞搜尋）, **When** 詳細頁面載入, **Then** 歌詞中不應該有任何高亮顯示
4. **Given** 搜尋關鍵字包含多個字詞, **When** 進入詳細頁, **Then** 所有匹配的字詞都應該被高亮

---

### User Story 3 - 自動捲動到第一個匹配位置 (Priority: P3)

當使用者透過歌詞關鍵字搜尋進入詳細頁時，系統應該自動將頁面捲動到第一個匹配的歌詞位置，避免使用者需要手動捲動尋找。

**Why this priority**: 這是錦上添花的功能，進一步減少使用者的操作步驟，但即使沒有此功能，使用者仍可透過視覺高亮找到匹配位置。

**Independent Test**: 搜尋出現在歌曲後半部的歌詞片段（如某首歌的副歌），點擊結果進入詳細頁，確認頁面自動捲動到該片段位置，而非停留在頂部。這個自動定位功能本身就能獨立提供價值。

**Acceptance Scenarios**:

1. **Given** 使用者透過歌詞關鍵字搜尋進入詳細頁, **When** 頁面載入完成, **Then** 頁面應該自動捲動到第一個高亮匹配的位置
2. **Given** 第一個匹配位置在歌詞的中間或底部, **When** 頁面載入, **Then** 匹配位置應該顯示在可視區域的中央或上方
3. **Given** 使用者透過歌名或歌手搜尋進入詳細頁, **When** 頁面載入, **Then** 頁面應該顯示在頂部（歌曲資訊開始處）

---

## Clarifications

### Session 2025-12-28

- Q: 高亮視覺樣式的具體設計 - 當前規格提到「視覺化高亮效果（例如背景色、粗體或下劃線）」，但缺乏具體的視覺規格 → A: 黃色背景 + 粗體組合
- Q: 無效歌曲 ID 的錯誤處理策略 - 當歌曲 ID 無效或歌曲已被刪除時，使用者應該看到什麼以及能做什麼 → A: 顯示 404 頁面（標準錯誤頁）
- Q: 直接透過 URL 進入詳細頁時的高亮顯示行為 - 當使用者直接透過 URL 進入詳細頁（不是從搜尋結果點擊）時，是否應該支援高亮顯示 → A: 支援，透過 URL query parameter（如 ?highlight=關鍵字）

### Edge Cases

- 當搜尋關鍵字在歌詞中出現非常多次（例如超過 50 次）時，系統如何處理高亮顯示的效能？
- 當 URL 中包含搜尋關鍵字參數但參數格式錯誤時，系統應該如何處理？
- 當搜尋關鍵字包含特殊字元（如 `*`, `?`, `/`）時，高亮功能是否正常運作？
- 當歌詞內容非常長（例如超過 200 行）時，頁面載入和捲動效能是否流暢？
- 當 URL 同時包含多個高亮關鍵字參數時，系統應該如何處理？

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系統必須在搜尋結果列表中的每個歌曲項目上提供可點擊的連結或按鈕，使使用者能夠導航到歌曲詳細頁面
- **FR-002**: 詳細頁面必須顯示完整的歌曲資訊，包括歌名、歌手名稱和完整歌詞內容
- **FR-003**: 系統必須支援透過 URL query parameter 傳遞高亮關鍵字(例如 `?highlight=關鍵字`),無論使用者是從搜尋結果進入或直接訪問 URL
- **FR-004**: 系統必須解析 URL 中的高亮關鍵字參數,並在歌詞內容中識別所有匹配的文字片段
- **FR-005**: 系統必須對所有匹配的歌詞片段套用組合式視覺化高亮效果：黃色背景配合粗體文字
- **FR-006**: 高亮效果必須清晰可辨，黃色背景與一般歌詞文字背景有明顯對比，粗體增強文字辨識度
- **FR-007**: 當 URL 中沒有高亮關鍵字參數時（例如從歌名或歌手搜尋進入，或直接訪問無參數的歌曲 URL），系統不應該顯示任何高亮效果
- **FR-008**: 詳細頁面必須提供返回功能（返回按鈕或支援瀏覽器返回鍵），讓使用者能夠回到搜尋結果頁面
- **FR-009**: 當使用者返回搜尋結果頁時，系統必須保持原有的搜尋狀態（搜尋關鍵字、結果列表、捲動位置）
- **FR-010**: 系統必須處理無效的歌曲 ID，當歌曲不存在時顯示標準的 404 錯誤頁面，說明資源未找到
- **FR-011**: 系統必須在頁面載入完成後，自動將視窗捲動到第一個高亮匹配的位置（如果有高亮的話）
- **FR-012**: 自動捲動時，匹配的歌詞片段應該顯示在可視區域內，不應該被遮蔽或位於邊緣

### Key Entities

- **歌曲 (Song)**: 代表一首完整的歌曲，包含歌曲 ID、歌名、歌手名稱、完整歌詞內容等屬性
- **搜尋上下文 (Search Context)**: 代表使用者從搜尋頁面帶來的上下文資訊，包含搜尋關鍵字、搜尋類型（歌詞、歌名或歌手）
- **歌詞片段 (Lyrics Fragment)**: 代表歌詞中與搜尋關鍵字匹配的文字片段，包含片段文字、在完整歌詞中的位置

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 使用者從點擊搜尋結果到看到完整歌曲詳細頁面的時間少於 2 秒
- **SC-002**: 當歌詞中有匹配關鍵字時，100% 的匹配文字都應該被正確高亮顯示
- **SC-003**: 使用者能夠在 1 次操作內從詳細頁返回到搜尋結果頁，且搜尋狀態保持不變
- **SC-004**: 頁面自動捲動功能的準確率達到 100%，第一個匹配片段始終在可視區域內
- **SC-005**: 系統支援包含至少 100 次關鍵字匹配的歌詞，且高亮顯示和捲動功能保持流暢（頁面載入時間少於 3 秒）
- **SC-006**: 95% 的使用者能夠在首次使用時成功完成「搜尋 → 點擊結果 → 查看詳細頁 → 返回」的完整流程

## Assumptions

- 假設歌曲資料已經存在於系統中（可能來自 API 或本地資料源）
- 假設搜尋結果頁面已經實作完成（根據 workspace 中的 004-lyrics-search）
- 假設系統使用 Vue Router 進行頁面導航
- 假設搜尋關鍵字可以透過 URL query parameter 傳遞（例如 `?keyword=愛`）
- 假設歌詞文字是純文字格式，不包含複雜的 HTML 結構
- 假設高亮顯示使用 CSS 樣式實作（黃色背景配合粗體，例如 `background-color: #ffeb3b; font-weight: bold`）
- 假設使用者使用現代瀏覽器，支援 JavaScript 和 CSS3
- 假設歌曲詳細頁的路由格式為 `/song/:id` 或類似結構

## Scope

### In Scope

- 從搜尋結果頁面到歌曲詳細頁面的導航功能
- 歌曲詳細頁面的基本 UI 佈局和內容顯示
- 歌詞文字中的關鍵字高亮顯示功能
- 自動捲動到第一個匹配位置的功能
- 從詳細頁返回搜尋結果頁並保持狀態
- 處理無效歌曲 ID 的錯誤情況

### Out of Scope

- 歌詞的編輯或修改功能
- 歌曲的播放或音訊功能
- 使用者評論或評分功能
- 歌詞翻譯或多語言版本
- 分享歌曲到社交媒體
- 收藏或加入播放清單功能
- 詳細頁面上的其他推薦歌曲
- 搜尋結果頁面的改進或優化（已在 004-lyrics-search 中處理）

## Dependencies

- 依賴 004-lyrics-search 功能已經完成，提供搜尋結果頁面
- 依賴 Vue Router 套件用於頁面導航
- 依賴現有的歌曲資料來源（API 或本地資料）
- 依賴現有的 Vue 組件架構和樣式系統
